# Written Offer Lifecycle

`draft → sent → accepted | rejected | expired | superseded`

A proposal is versioned and linked to the lead and, where available, the
consultation. A valid-until date must be selected before sending. Acceptance
requires an evidence note; rejection requires a reason. Terminal proposals
cannot be reopened. A new version supersedes an earlier proposal explicitly.

The Albanian PDF states that it is a proposal, not an active agreement; service
starts only after agreement and onboarding; third-party costs are separate;
founding status is bounded; and package price, price-lock treatment, inclusions,
exclusions, approval limits, validity, and next steps apply.

Acceptance permits existing client/property conversion. It never creates,
replaces, signs, approves, or activates a subscription/contract automatically.
